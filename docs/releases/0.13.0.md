# 0.13.0 — 会话状态可靠性更新

- 修复 Codex App 漏掉完成广播后仍显示运行中的问题，并保护新回合不被旧通知覆盖。
- 分别显示成功、失败、停止和等待输入；已读操作不改变任务结果或完成时间。
- 暂时无法确认状态时保留任务并显示“同步暂停”，恢复同步后重新核对；不把没有动静误报为成功或停止。
- 改善 WorkBuddy 结果判断、连续任务提醒、收起后的恢复，以及并发写入与状态文件损坏恢复。

## 当前尚不支持

Codex App 等待批准和等待输入的提醒暂不支持。任务长时间没有新动静时，插件可能显示“同步暂停”：这表示桌宠暂时无法确认任务状态，不代表任务已经停止。App 切换实例后的完整恢复、批准请求级提醒去重和无回合标识 hook 的严格排序仍待完善。

## 升级兼容

新版本写入 schema:3，兼容读取 schema:1/2。旧插件不能读取新格式；如需降级，须同时回退写入器并备份状态目录，不能直接将新状态改成旧格式。没有新增插件权限，不读取会话正文。

## English

Improves session status reliability: Codex App completion recovery, turn and read-state protection, distinct success/failure/stopped outcomes, paused-sync recovery, WorkBuddy results, notification deduplication, and concurrent/atomic status writes.

Codex App approval/input-wait notifications remain unsupported. “Sync paused” means the plugin cannot currently confirm the task status; it does not mean the task has stopped. Full recovery across App instances, per-request approval notification deduplication, and strict ordering for hooks without turn identifiers remain incomplete.

Writes schema:3 and reads schema:1/2/3. Older plugins cannot read the new format; downgrading requires rolling back writers and backing up the state directory. No new plugin permissions or conversation-content collection.

## 验证

沿用已完成的主分支验收：25 个离线套件、12 条隐藏隔离真宿主 E2E（包括 codex-state、codex-subagent、reliability、dismiss、waiting-accuracy）。其中 UI 对齐与 Codex 状态各有一次调试目标关闭，独立重跑通过；偶发关闭原因未定位。本次仅更新版本元数据与文档，不重复功能验收；发布 CI 再执行全部离线套件。
