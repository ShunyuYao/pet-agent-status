## 现有功能的适配

设计覆盖区域按在线节点修正。现有双状态汇总、设置齿轮、聚焦会话左缘白条、接入/移除钩子、安装后提示仍保留：这些是真实能力，不以静态设计样本替换业务数据。空态说明更新为当前设计文本，接入控件位于其下；空态可独立滚动，底栏固定。没有修改宿主代码、采集协议或状态规则。整合时保留主分支 `b4c70a1` 的面板即时回放修复，并把它的离线和真实开窗回归纳入同一门禁。

Figma和Chromium文字抗锯齿不同，不以整张PNG字节相等作为验收；检查几何、字号、字体加载、素材原始字节，并肉眼检查截图。未覆盖的原生失焦关闭、外部App真正激活、鼠标穿透不在本轮隐藏视觉测试的结论内。

## 可重跑门禁与证据

- `npm run test:offline`：全部离线测试，独立命名入口见package.json。
- `npm run test:figma-layout`：200项几何/素材/字体/空态/接入/重启断言；支持 `E2E_ARTIFACT_DIR` 指定证据目录。
- `npm run test:ui-e2e`：上条 + UI parity、启动器、收起、waiting准确性、列表滚动、面板即时打开；`npm run test:ui` 合并离线和UI门禁。
- 共享 `tests/e2e/hidden-host.js` 使用首帧前隐藏、独立profile与CDP端口，拷贝原始生产panel/lib/tool/assets并记录SHA256；仅外部应用探测、终端进程和OS执行采用夹具。采集、渲染、宿主SDK和存储真实。执行意图记录用于验证事件链，测试不激活日常应用。

## 宿主测试启动时序

首次主分支复核的两次重启，插件几何、字体、接入和持久化断言均通过，但宿主 `demo/index.html` 在输出渲染就绪日志之前发生 `binding.startupData=null` 的sandbox初始化异常，门禁据此失败。两条console记录来自同一次初始化失败，没有过滤或忽略它们。

测试helper现按每次启动的日志字节偏移，等待新的 `frames loaded`（宿主preload/API与资源完成后的真实就绪信号）再接入CDP；并单独检查接入前的原始host.log，防止延迟订阅漏掉初始化错误。此调整后的同一路径200项全部通过，原始host.log也无该异常。观察支持启动时序解释，但不声称已修改或定位Electron内部根因。宿主产品代码未改。原始失败事件保存在同目录 `initialization-failure.jsonl`。
