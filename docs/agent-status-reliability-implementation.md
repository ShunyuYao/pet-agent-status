# 会话状态可靠性：实现与验收记录

日期：2026-09-20。基线：0.12.6 / `2418d7d`。

**核心可靠性改动已经实现；Codex App 的等待批准、等待输入以及长时间无输出时的权威运行确认仍未实现，不能把整份 PRD 标为完成。** 原因是当前 App 没有向插件开放已验证的同实例、只含状态元数据的读取通道。插件已在设置中明确说明限制。

## 已实现的行为

- 已跟踪的 Codex App 回合即使没有完成广播，也会在下一次正常采集时用同轮明确终态纠正状态。新回合、旧任务内部运行 ID 变化、收尾日志追加和重启均受回合屏障保护。
- 正常完成、失败、停止、等待输入独立表示。App 已读仅改变 `read`，不刷新完成时间、不改变结果；迟到未读通知不能撤销同轮已读。
- 会话发现不算运行，闲置通知不复活任务。空会话关闭不产生完成记录；已有成功结果不会被随后的 SessionEnd 改成停止。未知 Claude 通知不猜成批准请求。
- 同步暂停保留最后确认的状态与时间，退出运行/批准/完成数量，不发成功气泡、不因长期无事件自动消失。坏文件单列诊断；本次运行已读过的记录临时损坏时保留最近记录并暂停同步，恢复后自动重读。
- WorkBuddy 的失败与终止不再按成功处理，pending 的输入等待独立显示。已跟踪记录即使掉出最近 20 条也继续按 ID 收尾。
- 连续两轮任务各自提醒；同轮重复事件、已读、重启不重复完成提醒。等待提醒按执行代次保存节流记录。收起按执行代次保存，重复写入同轮结果不会重新出现，新轮可见。
- 每个会话的写入串行并原子替换；较旧的显式时间戳不会覆盖较新记录。可恢复已退出进程留下的主写锁，活跃锁持有者不会被强占。
- 增加最近 100 条、30 天内的状态迁移诊断，只保存 ID、状态、来源事件和时间；相同状态心跳不重复记账，写失败后续重试。采样间隙内未观察到的事件不冒充完整记录。
- 修复增强开关异步读取竞态，旧读取结果不能覆盖用户刚修改的设置。
- 修复生命周期测试在最后几条用例执行之前便汇总退出码的漏洞；用故意失败的末尾用例验证会返回非零。

## 当前能力边界

本机检查版本：bundle `com.openai.codex`，App `26.915.31029` / build `9771`，安装目录名为 ChatGPT.app。

| 来源 | 当前可用依据 | 边界 |
|---|---|---|
| Codex App 运行活动 | 已归属任务的 rollout stat、回合编号和状态 | 文件活动是有时效的运行证据；静态 inProgress 查询不是新的心跳 |
| Codex App 正常结束/失败/停止 | thread_turns 同轮终态 | 只补正已跟踪任务，不导入历史完成；数据源写入延迟仍会影响可见时机 |
| Codex App 已读 | 被动 IPC read-state，加同轮终态核验 | 不把执行中的无回合编号通知预先记为新轮已读 |
| Codex App 批准/输入等待 | **不可用** | 已验证 IPC 不提供；回合数据库没有待批准请求；不读取完整会话流来提取状态 |
| CLI 批准等待 | Claude 明确权限通知、Codex PermissionRequest | 依赖 hook 真正启用并被上游发出；没有独立待批准请求快照或请求 ID |
| WorkBuddy 输入等待和结果 | SQLite 白名单列及元数据心跳 | 内部存储变化、锁库和心跳失效时降级为同步暂停 |

本轮检查的 App 包含 waitingOnApproval / waitingOnUserInput 内部标记，但这不代表外部插件可以读取。当前没有发现已开放的 app-server-control socket；连接另起的 App Server 不能代表正在运行的桌面实例。被动 IPC 的跟随流会涉及会话内容，因此没有为了获得等待状态而订阅它。

没有修改 App、宿主、用户信任文件或真实会话；没有自动批准、拒绝或发送消息。接口不可达时明确降级，不能声称已经实现批准提醒。

## 尚未满足的完整方案要求

1. ASR-006：真实 App 批准/输入等待的出现、处理、取消、多请求、重启回查及真源到宿主的完整验收。
2. ASR-005：30 分钟无输出但仍在执行时的权威确认，以及 App 实例切换的完整 epoch 恢复。当前证据过期会显示同步暂停；它不是“已停止”，也不是可靠的实时运行确认。
3. ASR-009 的请求级去重：当前只有回合/执行代次，CLI hook 没有稳定请求标识，等待仍按五分钟节流。
4. 全部来源的严格因果排序：写锁和显式回合屏障已落地，但不带源回合编号、事件序号的迟到 hook 仍只能按可用事件顺序处理。

后续必须先取得当前桌面实例的只读状态接口或元数据桥，再补以上验收。不能用猜测、超时或另起服务器替代。
