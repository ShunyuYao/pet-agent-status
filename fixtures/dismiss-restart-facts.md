# US-005 中断会话收起后重启复现（2026-09-13）

用户反馈：三个红色 Interrupted 的 Claude Code 会话，点掉后每次重启桌宠又出现。

## 只读取证

本机插件状态目录中恰有三条 Claude Code 记录仍是 `running`，末次事件均为
`Notification`，最后更新时间约在 25–30 小时前；对各自 PID 的存活探测均为已退出。
没有读取会话正文。采集器按既有规则将这些记录推导为 `error`。

`tool/index.js` 原先只在内存 `dismissedAt` Map 里保存用户的收起操作，且明确写着
“不落盘……重启后重新按真实状态显示”。状态文件保持原样，重启后 Map 为空，三条旧记录
再次进入面板。原有收起测试只覆盖同一宿主进程中的点击和新活动，缺少重启这一段。

## 自动复现先于修复

新增 `npm run test:dismiss-restart`，旁加载未修改的生产实现到隔离隐藏宿主：

1. 写入三条 30 小时未更新、PID 确定退出的真实协议记录，另留一条未点击的中断会话作阳性对照。
2. 确认面板真实推导出 `error`，行有可点击样式，派发 DOM click 后三条行消失。
3. 终止整个隔离宿主并用同一临时 profile 重启；原实现三条全部返回，重启断言失败。

## 修复边界

- 仅经现有 `pet.storage.get/set` 保存 `dismissedSessions`（sessionId → 已读时刻）。
  首次采集前恢复，加载期间的语言意图不会触发提前采集；面板 ready 订阅仍立即建立。
- 连续点击串行保存，SDK 读写拒绝时下轮重试。读失败时不以空表覆盖既存记录。
- 保留时间戳比较语义：有新事件则重新展示；`running/waiting` 不能被收起。
- 不修改 hook 状态文件，不采集正文，不变更 schema、状态推导、面板布局或宿主代码。
- 文件暂时读坏或缺失不会清掉已读；有更新事件时清掉旧标记，无对应记录超过 30 天才过期。

## 回归入口

- `npm run test:dismiss-persistence`：全离线，真实临时状态/存储文件与面板意图；覆盖首帧恢复、
  三条连续点击、慢写、SDK 错误恢复、暂时坏文件、新完成事件与多次重启。
- `npm run test:dismiss-restart`：真宿主进程重启，不依赖 collector.stop 的存储收尾；
  保留未点击及运行中/等待批准的对照。随后把真实 UserPromptSubmit JSON 喂给 hook stdin，
  确认仅该会话重新出现，且再次重启仍正确。断言原状态文件未被收起操作修改。
- 两个入口分别纳入 `test:offline` 和 `test:ui-e2e`；完整入口 `npm run test:ui`。

测试全程使用临时 userData、独立 CDP 端口与首帧前隐藏参数。导航命令由既有测试夹具记录，
不激活用户的终端；生产采集器、面板、事件桥和宿主持久化存储都是真实实现。
