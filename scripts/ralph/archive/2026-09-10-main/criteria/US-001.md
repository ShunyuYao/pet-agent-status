## 2. Model-Based Verification

- [ ] `manifest.json` 字段与宿主校验器兼容：对照宿主仓（只读）`demo/core/plugin-runtime/manifest.js` 逐字段核（id kebab-case、kind `["tool","panel"]`、permissions `["storage","pet","ui","events","scheduler"]`、`entry.tool` 指向 `tool/index.js`、`entry.panel.src='panel/panel.html'` width 320 height 420、version semver）
- [ ] `lib/state-files.js` 写路径流程：先写同目录 `.tmp-` 前缀临时文件再 `fs.renameSync`；目录不存在时 `mkdir -p`
- [ ] 读快照：`readSnapshots(dir)` 对损坏 JSON、缺必填字段（PROTOCOL.md 表）、schema>1 的文件跳过并归类 unknown 计数，绝不 throw
- [ ] sessionId 清洗：`[^A-Za-z0-9._-]` 替换 `_`，用 `../../etc/passwd` 这类输入断言落盘文件名安全
- [ ] `lib/i18n.js`：按 locale 取词、缺词回落 zh-CN；tool/panel/hooks 代码 `grep -P '[一-鿿]'` 零命中（中文只在 locales/*.json）

## 6. Common Failure Cases & Handling

- 写入非原子（直接 writeFileSync 目标路径）→ FAIL
- 损坏文件导致 readSnapshots throw → FAIL
- manifest 用了宿主不存在的 kind/字段 → FAIL（对照宿主源码，不凭记忆）
- 测试读写了真实 `~/.local/state` → FAIL（必须 mkdtemp）
