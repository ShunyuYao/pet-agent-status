# US-002 — Claude Code hooks 一键接入

## 1. Automated Verification (Code-Based)

- [ ] `node --check` 全部改动文件
- [ ] `node tests/claude-hook-test.js` 与 `node tests/claude-installer-test.js` 通过

## 2. Model-Based Verification

- [ ] `hooks/claude-status-hook.js` 是独立可执行脚本（宿主未运行时 Claude Code 也在调它）：只用 Node 内建，不 require 仓内其它模块以外的依赖；从 stdin 读完整 JSON；按 `hook_event_name` 走 PROTOCOL.md 映射；未知事件/解析失败/写盘失败一律 `process.exit(0)` 且不向 stdout 写会干扰 Claude Code 的内容
- [ ] tty 与 pid 采集：进程可得时写实值（`process.stdin` 非 tty 时经 `ps` 查父链或置 null），拿不到写 null 不猜
- [ ] 安装器 merge 语义：settings.json 已有的用户 hooks 条目逐字节保留；本插件条目带可识别标记（如 matcher/command 含 `pet-agent-status`）；重复安装不重复追加；`uninstall` 只删含标记条目
- [ ] 备份：写前复制原文件为 `.bak-pet-agent-status`（已存在不覆盖首份）；原文件不存在时创建合法最小结构
- [ ] hooks 事件注册覆盖：SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / Notification / Stop / SessionEnd

## 6. Common Failure Cases & Handling

- hook 脚本非零退出或向 stdout 打印垃圾（会干扰 Claude Code）→ FAIL
- 卸载后用户自有条目丢失/顺序被改 → FAIL
- 测试直调模块函数而非 spawn 喂 stdin → 自证，criteria 要求真实通道 → FAIL
- fixtures 与官方事件字段名不符（session_id/cwd/hook_event_name）→ FAIL
