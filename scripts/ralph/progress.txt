## US-001 返工（codex FAIL 修复）— DONE (commit 07ed3e1)

上轮双轨 codex 判 FAIL、仲裁 UPHELD，缺口属实，已修。

**缺陷**：`readSnapshots` 第 104 行用 `name.startsWith('.tmp-')` 过滤临时文件。但
PROTOCOL.md 的 sessionId 白名单 `[A-Za-z0-9._-]` 允许 ID 以 `.tmp-` 开头，
`sanitizeSessionId('.tmp-session')` 原样放行、写成正式文件 `.tmp-session.json`，
读侧却把它跳过 —— 该会话永远进不了快照，且 **不计入 unknown**（静默丢失、无诊断）。
写—读闭环自相矛盾，踩协议红线。

**根因（仲裁点破的关键事实）**：临时文件名是 `.tmp-<id>-<pid>-<rand>`，**本就不带
`.json` 后缀**，所以同一行的 `endsWith('.json')` 已经足以滤掉全部真实临时文件。
`startsWith('.tmp-')` 对临时文件是死代码，唯一的实际效果就是误杀合法会话 ——
没有任何正当收益抵消这个缺口。

**修法**：不是在读侧打补丁做例外，而是消除两种文件的命名歧义 ——
- 写侧临时文件显式补 `.tmp` 后缀（`.tmp-<id>-<pid>-<rand>.tmp`）；
- 读侧过滤依据单一化为「后缀是不是 `.json`」，删掉前缀判断。
两类文件在后缀维度天然互斥，不再靠前缀猜。

**证据**：
- 按 codex 报告原样复现（schema:1 必填齐全、sessionId=`.tmp-session`）：

- manifest 仍经宿主真实 `loadManifest` 加载通过。

**测试补强**：
- 新增「合法 `.tmp-` 会话可写入并读回」回归用例（锁死本次缺陷）。
- 新增「真临时文件与 `.tmp-` 会话同目录共存时各归各位」用例（防修复走偏成另一种误判）。

### 缺陷（属实，已独立复现）

`isOurs()` 按「分组内某条 command」**认领**，`uninstall`/`install` 却按**整个分组删除**。
Claude Code 的 `hooks.<Event>[].hooks` 是数组，一组可挂多条命令 —— 用户完全可能把自己的
命令追加进本插件写出的那个分组（配置里看着就是同一块，手改时最顺手）。此时卸载会把
用户那条连带抹掉，且毫无提示。

复现（/tmp 脚本，真实读写临时 settings.json，跑完已删）：
- install 后往 Stop 分组的 `hooks[]` 里追加 `{type:'command',command:'/Users/u/bin/user-notify.sh'}`
- uninstall
- 修前：`hooks` 整个变成 `undefined`，用户命令**消失**
- 修后：`hooks.Stop = [{hooks:[{type:'command',command:'/Users/u/bin/user-notify.sh'}]}]`，用户命令**保住**

### 根因与修法

根因是**删除粒度与身份粒度不一致**：认领看 command，删除看分组。
修法不是在 uninstall 里打补丁，而是把摘除逻辑单一化：
- 新增 `stripOurCommand(entry, command)`：只摘分组内我们那一条；分组还剩别的命令就
  保住该分组并**去掉 MARKER**（这组已不属于本插件，留着会让用户以为整组是插件的）；

### 缺陷属实，开工前先独立复现

`uninstall` 的删键条件写成「摘完为空就删 key」。这个判据**与「是谁创建的」无关** ——
用户原有的 `PreCompact: []` 会被静默删掉。复现（/tmp 脚本，跑完已删）：

- 原文 `{model:opus, hooks:{PreCompact:[], Stop:[用户的 /u/mine.sh]}}`
- install → uninstall
- 修前：`{"model":"opus","hooks":{"Stop":[...]}}` —— **PreCompact 键消失**
- 修后：与原文 deepStrictEqual 全等

**顺带查出裁决没点名、但同根的第二处**：用户原有的空 `hooks: {}` 容器同样被删
（修前落盘 `{"model":"opus"}`）。裁决的理由（用户原有的东西一律保留）对容器层
一字不差地成立，故一并修 —— 不是扩范围，是同一个判据漏在了上一个容器层级。

### 修法：删除权来自创建归属，不是「当前空不空」

install 在本插件标记条目内记录归属（`createdKey` / `createdHooks`），
uninstall 只删「本插件创建 **且** 摘除后为空」的键/容器。两个条件独立，须同时成立。

踩到并已处理的两个边界：

1. **重装必须沿用首次安装的归属判断**，不能按「本次安装前 key 在不在」重算 ——
   那时 key 已被上次 install 造出来，重算恒为 false，卸载再也收不回自己造的 key。
   实测（反证 C）：装两次再卸留下 7 个空数组键 —— 原缺陷的镜像。
2. **容器归属必须显式记录，不能从子元素归属反推**。我第一版就是用
   「本插件造了任一 key ⇒ 容器也是本插件的」反推，`hooks: {}` 用例当场判红：
   用户留空容器时 7 个 key 全是本插件造的，反推必然把用户的空容器删掉。
   归属这种事后无法从内容形态还原的信息，只能在创建时落盘记下。
