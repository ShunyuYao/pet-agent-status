# US-002 验收标准 — Claude Code hooks 一键接入

> 本文件由监工 2026-09-10 裁决后落盘（此前 criteria/ 目录缺失，第 2 轮验证的
> FAIL 判据悬空在 prd.json 的 verificationNotes 里）。以本文件为准。

## 1. hook 脚本（hooks/claude-status-hook.js）

- 从 stdin 读官方事件 JSON，按 PROTOCOL.md「事件 → state 映射」表写状态文件。
- 未知事件忽略，退出 0。
- **任何错误一律静默退出 0**（绝不阻塞 Claude Code）：解析失败、缺 session_id/cwd、
  状态目录不可写、库文件缺失等，退出码恒 0 且 stdout/stderr 零字节。
- `pid` 写 `process.ppid`（Claude Code 本体），不是 hook 自身 pid ——
  US-003 的 error 推导要靠它做存活探测。
- `tty` 尽力反查，拿不到写 `null`（协议允许），不猜。
- **不采集会话正文**：落盘 JSON 只含协议字段，prompt/工具输入等一律不出现。

## 2. 安装器（lib/claude-hooks-installer.js）

- merge 写入 `PET_AS_CLAUDE_SETTINGS` 指向的 settings.json；保留用户已有 hooks
  与其它顶层设置。
- **备份**：写前复制原文件为 `<file>.bak-pet-agent-status`；
  **已存在不覆盖首份** —— 备份语义是「回滚到本插件动手之前」，
  重复 install/uninstall 不得刷新它。
- 幂等：重复 install 不产生重复条目。
- uninstall 只摘除本插件条目；条目身份**只认 command**，
  marker 字段仅作人类可读标注，不得当身份判据。
- **摘除粒度 = command 粒度**（第 3 轮双轨 codex FAIL、仲裁 UPHELD 后补入）：
  `hooks.<Event>[].hooks` 是数组，一组可挂多条命令，用户可能把自己的命令
  追加进本插件写出的那个分组。身份判据既然是「分组内某条 command」，删除粒度
  就必须也是那一条 command —— 按整个分组删会连带抹掉用户的命令且毫无提示
  （不可逆的用户配置丢失）。分组内还剩别的命令时保住该分组并去掉 marker，
  只有整组空了才丢弃。install 的幂等去重与 uninstall 必须共用同一套摘除逻辑。
- **删键粒度 = 创建归属**（监工裁决 2、2026-09-10 补入）：uninstall 只允许删除
  「**本插件 install 时现造的** 且 摘除后为空」的事件 key；用户原有的 key
  （**含空数组** `PreCompact: []` 这类占位/临时停用写法）一律保留。
  空数组不是垃圾，是用户的配置内容 —— 本插件只有权收回自己造的东西。
  实现方式：install 在本插件标记条目内记录 `createdKey`；重装时沿用首次安装的
  判断（不可按「本次安装前 key 在不在」重算，那时 key 已被上次 install 造出来，
  重算恒为 false，卸载就再也收不回自己造的 key，反向留一堆空壳）。
  `hooks` 容器本身同理，需**显式记录**归属（`createdHooks`），
  不得从「key 是不是全是本插件造的」反推 —— 用户留一个空 `hooks: {}` 时
  7 个 key 全是本插件造的，反推会把用户的空容器删掉。
- 损坏的 settings.json：install 抛错而非当空文件覆盖（不可逆数据丢失）。
- **command 路径引号安全**（第 2 轮验证的范围外观察升格为验收项）：
  写进 settings.json 的 command 交给 shell 执行，node 路径与脚本路径都必须
  引起来。含 ASCII 空格的插件目录下，经 shell 执行该 command 必须 rc=0
  且能正常产出状态文件。

## 3. 卸载还原判据（第 2 轮验证后澄清，原「逐字节」要求过强）

原标准要求 install → uninstall 后与原文件**逐字节一致**。经裁决降为：

- **必须满足：语义等价 + 键序保持**。
  - `JSON.parse` 后与原文 `deepStrictEqual`；
  - 顶层键序与 `hooks` 下键序与原文一致（`Object.keys` 序列相等）。
- **保底：** 原文本身就是 `JSON.stringify(data, null, 2) + '\n'` 风格时，
  往返必须**逐字节相同**。
- 排版风格（4 空格 / tab / 紧凑单行 / `"key" : value` / 无末尾换行）
  不要求无损回放 —— JSON 排版无损往返对状态指示器插件性价比过低。

**测试夹具硬要求**：卸载还原用例的夹具**必须至少包含一种非 2 空格风格**
（如 4 空格或 tab）。第 2 轮验证指出，原夹具用 `JSON.stringify(c, null, 2)` 播种，
与被测实现 `writeSettings` 同源，断言恒真 —— 这是 US-001「夹具形态现实中不存在」
教训的同型复发，必须封死。

## 4. 测试

  （不许直调脚本内部函数自证），断言状态文件字段与映射
  （SessionStart/UserPromptSubmit→running、Notification→waiting、
  Stop→done、SessionEnd→ended）。
- `tests/claude-installer-test.js`：安装 → 再安装（幂等）→ 卸载三段全绿，
  含 §2 备份首份不覆盖、§3 语义等价+键序（非 2 空格夹具）、
  §2 引号安全（含空格目录实跑）、§2 摘除粒度（**同一分组内**用户追加的
  命令必须保留 —— 只造「不同分组」的不误伤用例覆盖不到这个缺口）、
  §2 删键粒度两条硬断言：
  ① 用户已有 `PreCompact: []` 时 install→uninstall 后该键仍在且为 `[]`
  （**deepStrictEqual 全对象**，不只查该键在不在）；
  ② 本插件创建的键卸载后彻底消失（不留空壳）。
- 夹具漂移：`fixtures/claude-code-events/*.json` 是监工用真实会话实录回填的，
  `session_id`/`cwd` 会随重录而变。断言**必须从夹具现读**，不许把某次录制的
  字面值抄进测试 —— 抄了就把测试绑死在一份录制上，换录制即红，且红的原因
  与被测行为无关。
- 全离线：mkdtemp + `PET_AGENT_STATUS_DIR`/`PET_AS_CLAUDE_SETTINGS` 覆盖，
  绝不读写真实 `~/.claude`、`~/.local/state`；并把隔离自证写成断言。
